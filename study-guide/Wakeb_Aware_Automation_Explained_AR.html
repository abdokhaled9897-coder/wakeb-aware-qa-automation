ابدأ من هنا

المشروع ده فيه Login بستة سيناريوهات، ودورة Tickets من إنشاء Report من مخالفة إلى Resolved. هنشرحه على نسخة Wakeb_Aware_Automation_Practice الموجودة فعلًا، مش على النسخ القديمة Java27 أو Simple.

فكرة Page Object Model هنا بسيطة: LoginPage وTicketsPage يمثلوا صفحات وتعاملات الموقع، وLoginTests وTicketsTests يمثلوا سيناريوهات الاختبار. BaseTest يجمع تجهيز المتصفح وإغلاقه، وConfigReader وDriverFactory أدوات مشتركة.

وجود components package فاضي في التري مش معناه وجود كود لازم نحفظه. المهم الكلاسات الفعلية اللي هتقرأها تحت.

الشرح مبني على قراءة ملفات المشروع، وليس إعادة تشغيل جديدة للاختبارات. الكود مضمّن كما هو؛ لم نغيّر مصادر المشروع أثناء إعداد الشرح. لا يوجد باسورد فعلي في الدليل.

طريقة المذاكرة

اقرأ الفكرة وخريطة التنفيذ الأول. بعد كده خد ملفًا واحدًا: اقرأ وظيفته، راجع الكود، ثم اقرأ تفسير كل جزء تحته. جرّب تحكي دور الملف بصوتك قبل ما تنتقل للبعده.

Java / Selenium / TestNG / MavenJava هي اللغة. Selenium بيحرّك المتصفح. TestNG بينظّم تشغيل الاختبارات ونتائجها. Maven بيقرأ pom.xml ويحمل المكتبات ويبني المشروع.
Class / Objectالكلاس وصف للحاجة؛ مثل LoginPage. الـObject نسخة شغالة منه. new LoginPage(driver) بينشئ نسخة مرتبطة بالمتصفح الموجود.
Constructorدالة تجهيز اسمها نفس اسم الكلاس، من غير نوع إرجاع. بتشتغل وقت new. هي مش التيست ومش دالة فتح المتصفح تلقائيًا.
this.driver = driverاليمين هو المتصفح اللي اتبعت للكونستراكتور. الشمال هو متغير الكلاس. كده الصفحة تستخدم نفس المتصفح، مش متصفح جديد.
public / private / protectedpublic متاح من خارج الكلاس. private للاستخدام داخل نفس الكلاس. protected يخلي الكلاسات الوارثة تقدر تستخدم العضو، وكمان نفس الـpackage.
static / final / abstractstatic يخص الكلاس ويمكن استدعاؤه من غير new. final على المتغير يمنع إعادة إسناده، وليس تغيير محتوى كل Object. final على الكلاس يمنع الوراثة. abstract كلاس أساس لا ننشئ منه Object مباشرة.
String / int / boolean / voidString نص، int رقم صحيح، boolean إما true أو false. void معناها الدالة لا ترجع قيمة. return بيرجع نتيجة ويُنهي تنفيذ الدالة الحالية.
extends / superextends توريث أعضاء وسلوك من كلاس أساس. super(driver) يستدعي كونستراكتور الأب ويمرّر له نفس المتصفح.
By / WebElementBy وصف مكان العنصر؛ مثل عنوانه. WebElement هو العنصر اللي Selenium لاقاه فعليًا. لو الصفحة أعادت رسم العنصر، مرجع WebElement القديم ممكن يبقى stale.
import / packagepackage يحدد مكان الكلاس المنطقي. import يسمح باستخدام اسم كلاس من مكتبة أو package أخرى من غير كتابة اسمه الكامل كل مرة.
WebDriver / ChromeDriverWebDriver واجهة أوامر المتصفح. ChromeDriver هو التنفيذ الخاص بكروم. WebDriver driver = new ChromeDriver(...) يخلينا نتعامل مع كروم من خلال الواجهة.
CSS Selector / XPathCSS يحدد العنصر بخصائصه أو كلاساته. XPath يسمح كمان بالتنقل للأب وبالاختيار حسب النص. normalize-space() يزيل المسافات الزائدة عند مقارنة النص.
By.id / By.cssSelector / By.xpathالأولى للـid، الثانية لمحدد CSS، الثالثة لتعبير XPath. الـid المتغير مثل input-v-... لا نعتمد عليه؛ نختار خاصية ثابتة مثل placeholder أو id معنوي ثابت.
WebDriverWait / untilانتظار بشرط ولمدة قصوى. لو الشرط تحقق بدري يكمل فورًا. مش معناه إن كل خطوة تستنى المدة كاملة.
presence / visibility / clickablepresence: العنصر موجود في DOM. visibility: موجود وظاهر وله مساحة. clickable: ظاهر ومفعّل؛ لكنه وحده لا يضمن إن مفيش نافذة تانية مغطياه.
DOM / getDomProperty / getDomAttributeDOM تمثيل عناصر الصفحة. property مثل value تقرأ القيمة الحالية أثناء التشغيل. attribute تقرأ خاصية العنصر مثل readonly أو aria-selected.
Assertتحقق يحدد نجاح التيست. assertEquals يقارن الفعلي بالمتوقع. assertTrue يشترط true. assertFalse يشترط false. الضغط على Save وحده لا يثبت نجاح الحفظ.
! / && / || / == / equals! يعكس boolean. && يعني الشرطان معًا، || واحد منهما يكفي. == يقارن أرقامًا وboolean أو هوية Objects؛ نقارن محتوى النص باستخدام equals أو equalsIgnoreCase.
null / isBlank / isEmptynull يعني مفيش مرجع لقيمة. isEmpty يعني طول النص صفر. isBlank يشمل النص الفاضي والمسافات. لازم نتأكد من null قبل استدعاء دالة على المتغير.
try / catch / finally / throw / throwstry نجرب تنفيذًا قد يفشل. catch يعالج نوع خطأ محدد. finally ينفذ التنظيف. throw يرمي خطأ فعليًا. throws يعلن إن الدالة قد تمرّر الخطأ لمن استدعاها.
IOExceptionتنطق آي أو إكسبشن. خطأ إدخال/إخراج، مثل مشكلة قراءة ملف. الاسم جزء من Java مش اسم إحنا اخترناه.
IllegalStateException / IllegalArgumentExceptionالأولى حالة غير مناسبة للتنفيذ، مثل إعداد مطلوب ناقص. الثانية قيمة وسيط غير مقبولة، مثل طلب متصفح غير مدعوم. برضه أسماء أنواع أخطاء جاهزة في Java.
d -> ...دي lambda: دالة صغيرة بنمررها للانتظار. d هو المتصفح في كل محاولة. رجوع false أو null يخلي الانتظار يحاول تاني لحد النجاح أو انتهاء الوقت.
for / List / StringBuilderfor تكرر تعليمات. List قائمة عناصر. StringBuilder يجمع أجزاء نص بشكل مناسب داخل التكرار. getFirst() يرجع أول عنصر من القائمة.
Path / Filesأدوات Java للتعامل مع مسار الملف والتحقق من وجوده وكتابة الصورة. المسار النسبي بيتحسب من Working directory الحالي للمشروع.
Test method / Page methodدالة الصفحة تنفذ تعاملًا مع الواجهة. دالة التيست تروي السيناريو وتتحقق من نتيجته. بعض دوال الصفحة هنا تتضمن انتظارًا وتحققًا داخليًا أيضًا.
BeforeMethod / AfterMethodTestNG ينفذ BeforeMethod قبل كل Test وAfterMethod بعد كل Test. مش مرة واحدة لكل الملف. alwaysRun=true يساعد التنظيف يشتغل حتى مع حالات الفشل.
priority / groups / descriptionpriority في TestNG ترتيب تنفيذ، مش خطورة البج. groups تصنيف اختبارات. description وصف يظهر في التقرير، وليس أمر تشغيل أو تحققًا في حد ذاته.
Thread.sleep(5000)توقف ثابت خمس ثواني. في نهاية التيست هنا لإتاحة رؤية النتيجة. مختلف عن WebDriverWait اللي ينتظر شرطًا ويتحرك فور تحققه.
Environment variable / System propertySystem.getenv يقرأ متغير بيئة وصل لعملية التشغيل. System.getProperty يقرأ Java system property مثل -Dtimeout.seconds=30. دول مصدران مختلفان.

الكود الكامل كما هو في المشروع

package com.wakeb.aware.config;

import java.io.IOException;
import java.io.InputStream;
import java.util.Properties;

public class ConfigReader {

    public static String get(String key) throws IOException {

        Properties properties = new Properties();

        try (InputStream file = ConfigReader.class
                .getResourceAsStream("/config.properties")) {

            if (file == null) {
                throw new IOException("config.properties was not found");
            }

            properties.load(file);
        }

        return properties.getProperty(key);
    }
}

4. DriverFactory.java

src/main/java/com/wakeb/aware/driver/DriverFactory.java

مكان واحد لإنشاء جلسة المتصفح.

الكود الكامل كما هو في المشروع

package com.wakeb.aware.driver;

import com.wakeb.aware.config.ConfigReader;
import java.io.IOException;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.chrome.ChromeDriver;
import org.openqa.selenium.chrome.ChromeOptions;

public class DriverFactory {

    public static WebDriver createDriver() throws IOException {

        String browser = ConfigReader.get("browser");

        if (!"chrome".equalsIgnoreCase(browser)) {
            throw new IllegalArgumentException("Only Chrome is supported");
        }

        ChromeOptions options = new ChromeOptions();
        options.setExperimentalOption("detach", true);

        boolean headless = Boolean.parseBoolean(
                ConfigReader.get("headless")
        );

        if (headless) {
            options.addArguments("--headless=new");
        }

        WebDriver driver = new ChromeDriver(options);
        driver.manage().window().maximize();

        return driver;
    }
}

شرح الكود

الجزءمعناه في المشروع
createDriver()دالة static نستدعيها باسم الكلاس. ترجع WebDriver جاهز لاستخدام صفحات الموقع.
!"chrome".equalsIgnoreCase(browser)يقارن اسم المتصفح من غير حساسية لحالة الحروف. ! يعني لو الاسم مش chrome نوقف برسالة Only Chrome is supported. وضع النص الثابت على الشمال يتجنب NullPointerException لو الإعداد ناقص.
ChromeOptionsإعدادات نمررها إلى ChromeDriver قبل فتح كروم.
detach=trueيسمح ببقاء كروم بعد انتهاء عملية الاختبار إذا لم تُنهَ الجلسة. لا يمنع driver.quit من إغلاقها؛ قرار الاستمرار الأساسي عندنا keepBrowserOpen.
Boolean.parseBoolean / headlessتحويل النص true أو false إلى boolean. لو headless=true نضيف --headless=new.
new ChromeDriver(options)ينشئ جلسة Chrome فعلية. لم نضف WebDriverManager كمكتبة منفصلة في المشروع.
maximize / returnيكبّر النافذة ويرجع نفس المتصفح للكود اللي طلبه.

package com.wakeb.aware.tests;

import com.wakeb.aware.driver.DriverFactory;
import java.io.IOException;
import org.openqa.selenium.WebDriver;
import org.testng.annotations.AfterMethod;
import org.testng.annotations.BeforeMethod;

public class BaseTest {

    protected WebDriver driver;
    protected boolean keepBrowserOpen;

    @BeforeMethod
    public void setUp() throws IOException {
        keepBrowserOpen = false;
        driver = DriverFactory.createDriver();
    }

    @AfterMethod(alwaysRun = true)
    public void tearDown() throws InterruptedException {
        if (driver != null && !keepBrowserOpen) {
            Thread.sleep(5000);
            driver.quit();
        }
    }
}

package com.wakeb.aware.pages;

import com.wakeb.aware.config.ConfigReader;
import java.io.IOException;
import java.time.Duration;
import org.openqa.selenium.By;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.support.ui.ExpectedConditions;
import org.openqa.selenium.support.ui.WebDriverWait;

public class LoginPage {

    private WebDriver driver;
    private WebDriverWait wait;

    private By emailField =
            By.cssSelector("input[placeholder='Enter Email']");

    private By passwordField =
            By.cssSelector("input[placeholder='Enter Password']");

    private By signInButton =
            By.cssSelector("button[type='submit']");

    public LoginPage(WebDriver driver) throws IOException {
        this.driver = driver;

        int timeout = Integer.parseInt(
                ConfigReader.get("timeout.seconds")
        );

        wait = new WebDriverWait(driver, Duration.ofSeconds(timeout));
    }

    public void open() throws IOException {
        driver.get(ConfigReader.get("base.url") + "/login");

        wait.until(
                ExpectedConditions.visibilityOfElementLocated(emailField)
        );

        Assert.assertEquals(ticketsPage.getPriority(), "Medium");
        Assert.assertTrue(ticketsPage.getDetailsText().contains(description));
        Assert.assertTrue(ticketsPage.getDetailsText().contains(ConfigReader.get("ticket.detection.type"))); 
        Assert.assertTrue(ticketsPage.getDetailsText().contains(ConfigReader.get("ticket.report.to")));
        Assert.assertTrue(ticketsPage.hasAttachment(), "The saved ticket attachment is missing.");

        ticketsPage.addComment(comment);
        ticketsPage.changePriority("High");
        ticketsPage.close();
        ticketsPage.openTicket(title);
        Assert.assertEquals(ticketsPage.getPriority(), "High", "Priority was not saved.");
        Assert.assertTrue(ticketsPage.getDetailsText().contains(comment), "Comment was not saved.");

        ticketsPage.changeStage("In Analysis");
        ticketsPage.openHistory();
        Assert.assertTrue(wait.until(ExpectedConditions.textToBePresentInElementLocated(
                By.cssSelector(".card-detail-modal"), "to In Analysis")));
        ticketsPage.close();
        ticketsPage.openTicket(title);
        Assert.assertEquals(ticketsPage.getStage(), "In Analysis", "Stage was not saved.");

        ticketsPage.changeStage("Resolved");
        ticketsPage.openHistory();
        Assert.assertTrue(wait.until(ExpectedConditions.textToBePresentInElementLocated(
                By.cssSelector(".card-detail-modal"), "to Resolved")));
        ticketsPage.close();
        ticketsPage.openTicket(title);
        Assert.assertEquals(ticketsPage.getStage(), "Resolved", "The ticket was not resolved.");
        Assert.assertEquals(ticketsPage.getPriority(), "High");
        Assert.assertTrue(ticketsPage.getDetailsText().contains(comment));
        ticketsPage.close();

        row = ticketsPage.getTicketRowText(title);
        Assert.assertTrue(row.contains("Resolved"), "The table should show Resolved.");
        Assert.assertTrue(row.contains("High"), "The table should show High priority.");
        System.out.println("Ticket lifecycle passed: " + title);
    }
}

تتبع التشغيل والمذاكرة العملية

مثال تتبع: شغّل login.xml. TestNG يجهز BaseTest.setUp أولًا لأنه في الكلاس الأب، ثم openLoginPage في LoginTests. بعدها ينفذ السيناريو حسب priority. لو البيانات غلط، المطلوب ظهور رسالة رفض؛ دي نتيجة نجاح للتيست السلبي.

في سيناريو ناجح: enterEmail وenterPassword يملؤوا النموذج. signIn ينتظر زر الدخول مع حل CAPTCHA يدويًا. successfulLogin ينتظر Events ثم يترك المتصفح. بعده tearDown يقرأ keepBrowserOpen=true فلا يغلق النافذة.

في Tickets: اقرأ ticketLifecycle من فوق لتحت؛ كل اسم دالة في TicketsPage يشرح خطوة واضحة. اختَر openTicket وشوف إزاي يبحث عن العنوان الصحيح ثم يفتح View. اختَر changeStage وشوف التحقق المحلي في الحقل، ثم ارجع للتيست وشوف إعادة الفتح التي تثبت الحفظ.

للتشغيل من IntelliJ: افتح المشروع من pom.xml، استخدم JDK 27 واعمل Sync Maven، واضبط AWARE_EMAIL وAWARE_PASSWORD في Environment variables لنفس Run Configuration. شغّل login.xml أو tickets.xml من src/test/resources/testng. لو ظهرت رسالة Set AWARE_EMAIL تأكد إنك عدلت إعداد التشغيل اللي بتشغله فعلًا.

لا تستخدم باسوردًا فعليًا داخل screenshots أو مستندات المذاكرة. القيم WrongPassword123! وTestPassword123! في الكود بيانات تجريبية مقصودة، وليست حسابًا صالحًا.

نطاق التحقق: شرحنا السبع @Test الموجودة، وليس تغطية كاملة للموقع. تسجيل CAPTCHA يدوي يجعل الدخول هنا assisted automation. هذه الجلسة لم تعد تشغيل Aware؛ نجاحه السابق لا يمثل تشغيلًا جديدًا بتاريخ الشرح.

TimeoutException يعني الشرط المطلوب لم يتحقق في الوقت؛ راجع الصفحة والعنصر واللغة وCAPTCHA قبل القول إن ده بج موقع. ElementClickInterceptedException يعني إن الضغط اتغطى بعنصر آخر. الخروج exit code=0 وحده ليس كافيًا لو واجهة TestNG أظهرت Fail؛ اقرأ عدد النتائج وتفاصيل Assert.

تقديم المشروع في بريزنتيشن

أنا استخدمت Java مع Selenium وTestNG وMaven. قسمت المشروع لصفحات فيها عناصر الموقع والتعاملات معها، واختبارات فيها السيناريو والتحقق من النتيجة. الإعدادات في ملف مستقل وبيانات الحساب في Environment variables. بستخدم انتظار بشرط بدل انتظار ثابت لكل خطوة، وبعيد فتح البيانات بعد تعديلها علشان أتأكد إن الحفظ مستمر. بعد كده أشرح سيناريو كامل من أول تجهيز المتصفح لحد آخر Assert، وأوضح الجزء اليدوي وحدود التغطية لو موجودين.
